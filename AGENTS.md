# AGENTS.md

## Scope

These instructions apply to the entire repository.

## Project overview

Typograf is a TypeScript library for client- and server-side typography. It applies ordered, locale-aware text transformation rules and publishes CommonJS, ES module, browser, CSS, and type declaration artifacts.

Use Node.js 24 when possible; that is the version used by CI. Install the exact dependency tree with `npm ci`.

## Repository map

- `src/main.ts`: the `Typograf` engine and public types.
- `src/typograf.ts`: the default entry point; loads locale data and all bundled rules.
- `src/rule.ts`: global rule registration, preparation, and ordering.
- `src/rules/<locale>/<group>/`: rule implementations, titles, tests, and group registration.
- `src/data/`: locale-specific data registered by `src/data/index.ts`.
- `src/helpers/`: shared low-level helpers.
- `test/`: API, integration, format, fixture, and compatibility tests.
- `tools/`: build-time generators for titles, rule documentation, and package artifacts.
- `docs/`: user-facing documentation; the `RULES*.md` catalogs are generated.

## Sources of truth and generated files

- Treat `src/` as the source of truth for runtime behavior.
- Do not edit `build/`, `dist/`, `coverage/`, or `src/version.ts` by hand. They are generated and ignored by Git.
- Rule titles come from adjacent `src/rules/**/*.json` files.
- Rule group labels come from `src/groups.json`; ordering offsets live in `src/groupIndexes.ts`.
- `docs/RULES*.md` and `docs/RULES_SORTED*.md` are generated by `tools/md.mjs`. When the published rule catalog changes, regenerate them with `npm run dist` and review the resulting documentation diff.
- Keep `package-lock.json` in sync with `package.json`; do not replace `npm ci` with an unpinned install in CI-oriented work.

## Working on rules

Rule names have the form `<locale>/<group>/<rule>`, for example `common/space/afterComma`. `common` rules apply across locales; locale-specific rules apply to the primary selected locale. Execution order is controlled by the rule queue and numeric index, so avoid changing either without checking interactions with neighboring rules.

When adding a rule:

1. Add `<rule>.ts` under the appropriate locale and group, exporting a named `TypografRule` object.
2. Add `<rule>.json` with the user-facing English and/or Russian titles used by the documentation generator.
3. Add a colocated `<rule>.test.ts` using the helpers from `test/helpers`.
4. Import and register the rule in the group's `index.ts` with `Typograf.addRules` or, only for preprocessing rules, `Typograf.addInnerRules`.
5. If introducing a locale or group, also wire its parent indexes and locale data, and update `src/groups.json` or `src/groupIndexes.ts` where appropriate.

Every behavioral fix should include a regression case. Cover both the transformation and important non-matches. Rule behavior should be idempotent: applying a rule twice must produce the same result as applying it once. The shared test helpers enforce this for enabled rules.

Preserve the existing TypeScript style: four-space indentation, single-quoted strings, semicolons, small focused functions, and explicit exported types where they clarify the public API. The compiler targets ES5, so do not introduce runtime APIs that require an unprovided polyfill.

## Validation

Run the narrowest relevant check while iterating, then the repository checks before handoff:

```sh
npx jest src/rules/<locale>/<group>/<rule>.test.ts --runInBand
npm run typecheck
npm run eslint
npm test
```

`npm test` rebuilds the first-stage artifacts, runs ESLint, and runs the full Jest suite with coverage. Use `npm run dist` when release artifacts or generated rule documentation must be refreshed. Run `npm run benchmark` for changes to hot paths, regex-heavy rules, rule iteration, or safe-tag processing.

## Change discipline

- Check `git status` before editing and preserve unrelated user changes.
- Keep patches focused; avoid formatting or regenerating unrelated files.
- Do not change public behavior, rule ordering, defaults, or supported locale data without tests and matching documentation when applicable.
- Review generated diffs before committing them; unexpected changes often indicate that rule registration, titles, or ordering changed.
